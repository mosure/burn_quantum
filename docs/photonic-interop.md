# Local PsiQDK interoperability

`photonic::interop::OpenQasm3` exports a bound `Circuit` to a documented OpenQASM3
subset that has been executed with the public **PsiQDK 2.5.0** SDK. This is local
simulator interchange. It does not submit jobs to PsiQuantum hardware, authenticate
with a provider, or turn a logical circuit into a calibrated photonic fabric.

The integration uses the official
[Workbench OpenQASM import interface](https://docs.construct.psiquantum.com/psiqdk-workbench/new-tutorials/Exporting-to-OpenQASM.html):
`QasmString(text).add_operations_to_qpu(qpu)`, followed by `qpu.pull_state()`.
The generator explicitly chooses the `state-vector-sim` and `buffer` filters.
There is no alternate provider, SDK version, or missing-dependency fallback.

## Export contract

```rust
use burn_quantum::{Circuit, Register, Rotation, Angle, gate::Axis};
use burn_quantum::photonic::interop::{OpenQasm3, OpenQasmOptions};
let mut circuit = Circuit::new(Register::qubits(2)?, 1, 0);
circuit.rotate(0, Rotation::qubit(Axis::Y, Angle::parameter(0)))?;
circuit.controlled_x(vec![(0, 1)], 1)?;
let exported = OpenQasm3::export(
    &circuit, &[0.7], &[], &[1, 0], OpenQasmOptions::default(),
)?;
assert_eq!(exported.readout_wires(), &[1, 0]);
# Ok::<(), burn_quantum::Error>(())
```

One call binds one parameter vector and one feature row. Binding widths must
exactly match the circuit; all values and resulting affine angles must be finite.
Qudit registers are rejected. Structured controls and bounded dense unitaries
reuse `GateSynthesis`; arbitrary one-qubit U(2) gates then become RZ/RY/RZ,
while CNOT, CZ, and SWAP remain direct primitives. Reversed two-level Y/Z
rotations negate the angle. Existing synthesis and reconstruction diagnostics
remain explicit, with the extra Euler residual included in the numerical budget.

`OpenQasmOptions` bounds wires, UTF-8 bytes, native synthesis work, predicate size,
opaque unitary size, and host reconstruction error. The byte budget is checked
on each emitted statement, and also limits the intermediate native gate count.
Exporting is synchronous host work; it neither evaluates Burn tensors nor
pretends to preserve an autodiff graph across a text/SDK boundary. Users bind
separate parameter probes or batched feature rows explicitly.

The program resets every logical wire to |0> before running. It optionally emits
terminal computational-basis measurements. Mid-circuit adaptive classical logic,
reset within the source circuit, general quantum channels, and instrument/factory
provenance are outside this interchange subset; none are silently removed.

## Wire, phase and measurement mapping

Source wire i is always OpenQASM `q[i]`. Burn stores amplitude indices with wire
zero most significant; PsiQDK uses q[i] as little-endian bit i.
`psiqdk_index(burn_index)` performs the checked bit reversal. No quantum SWAP is
inserted to conceal this representation difference.

The export is equivalent **up to one overall global phase**. This applies to
native synthesis as well as U(2) Euler conversion, and is stated in both the API
and the exported text. It is not a phase-preserving controlled-subroutine
interface. Structured controlled operations inside the original circuit are
synthesized before exporting, so their physically meaningful relative phases are
retained. State comparisons align exactly one global phase for the full circuit;
they compare every complex amplitude and probability, not only final fidelity.

For readout list `[w0,w1,...]`, emitted classical `c[j]` measures `q[wj]`.
Workbench returns a list in measurement order with values zero or `2^wj`, as
specified by its import interface. `decode_psiqdk_readouts` validates that weighting
and returns ordinary booleans. Duplicate readout wires, missing values, or values
weighted for the wrong wire are rejected. A terminal readout collapses the SDK
state; statevector comparisons therefore use unmeasured cases, or deterministic
computational-basis cases where the result is known.

## Pinned independent execution

The committed
[fixture](../crates/burn_quantum/tests/interop/psiqdk-2.5.0.json) was generated by
actually running four exported circuits in the SDK, using Python **3.12.13** and:

| Package | Version |
|---|---|
| psiqdk | 2.5.0 |
| psiqdk-workbench | 4.55.3 |
| workbench-sim-native | 0.3.0 |
| antlr4-python3-runtime | 4.13.2 |
| numpy | 2.5.4 |

The parser dependency is explicitly required by the official import tutorial.
The generator rejects different package versions and non-3.12 Python. It records
the source circuits, bindings, exact exported text, SHA256 of each program,
SDK complex amplitudes, package versions, execution pipeline, and actual weighted
measurement results. Its source circuits come from the single-file
[`psiqdk_interop`](../crates/burn_quantum_example/src/bin/psiqdk_interop.rs) example.
The SDK output is independently computed; native amplitudes are not copied into
the fixture. Rust guards require all five package versions, the recorded Python
version, schema, phase/wire contracts, all four named cases, and their audited
SHA256 identities, in addition to regenerating the complete instruction stream.
Gate names, wire identities, order and all non-rotation text match exactly;
rotation literals allow at most four F64 ULPs of host roundoff. GitHub's runner
and the fixture host differed by one ULP in a synthesized Fourier rotation.
The fixture bytes and audited hashes remain unchanged. Negative tests reject
larger angle errors, nonfinite values and changed gates or wires. The generator
computes the hashes; Rust tests require no hashing subprocess.

The four cases exercise asymmetric wire usage and affine bindings with a general
complex U(2), mixed-polarity multicontrols and non-Clifford gates, a dense Fourier
gate on reordered wires with reversed rotation levels, and nontrivial terminal
measurement order. `psiqdk_interop` integration tests deserialize the source,
regenerate the OpenQASM program, execute it natively on the selected Burn
device, map SDK indices, align global phase, and compare every amplitude with
absolute tolerance **3e-6**. The deterministic readout example returns `[4,1,0]`
for wires `[2,0,1]`, decoded as `[true,true,false]`.

To reproduce with an isolated Python3.12 environment, install the exact five
packages in the table, then run:

```sh
python crates/burn_quantum/tests/interop/regenerate_psiqdk.py
cargo test --locked -p burn_quantum --test psiqdk_interop
cargo run --locked -p burn_quantum_example --bin psiqdk_interop
BURN_QUANTUM_DEVICE=wgpu cargo test --locked -p burn_quantum --features wgpu,fusion --test psiqdk_interop
```

The regeneration script runs the Rust example on CPU to obtain export inputs,
then the explicit local SDK simulator. Rust fixture tests need no Python or
network access. Native CPU/GPU qualification remains recorded separately in the
repository's executed validation matrix; a compiled feature is not device-runtime
evidence. Emitted/native gate counts and numerical diagnostics describe this
export, not a photonic hardware resource estimate or a claim about PsiQDK's own
internal optimized gate count.
